Contexto y Oportunidad

El Desafío de la Venta Conversacional

  • Demora en Atención: Los clientes de e-commerce exigen respuestas inmediatas en canales como WhatsApp. Si no respondes en 5 minutos, la venta se pierde.
  • Carga Operativa: Responder manualmente preguntas de stock, enviar fotos y registrar datos de pedidos satura a los equipos comerciales.
  • Desconexión de Datos: Las conversaciones se quedan en teléfonos individuales y no se centralizan en una base de datos ni sistema de control.

Atención 24/7 ineficiente

Perder ventas por falta de personal disponible fuera de horarios de oficina o fines de semana.

Control de stock ciego

Vender productos sin validar inventarios reales, provocando quiebres de stock y molestando al cliente.

La Propuesta

Presentando MiniBot CRM

WhatsApp Cloud API

Conexión directa con la API oficial de Meta para enviar respuestas instantáneas estructuradas y fichas de productos con imagen.

Base de Datos Relacional

PostgreSQL (Supabase) centralizado. Persistencia e integridad referencial de clientes, productos, stock y mensajes.

CRM Administrativo

Panel web minimalista para auditar transacciones, visualizar estadísticas y disparar confirmaciones de pedidos con webhooks seguros.

Tecnología

Arquitectura del Sistema

  • Backend (Node.js + Express): Servidor que maneja los webhooks de Meta y expone la API de solicitudes del CRM.
  • Máquina de Estados en BD: El estado conversacional se guarda en PostgreSQL. Cero pérdidas si el servidor se apaga.
  • Transacciones Atómicas: Implementación de db.tx (pg-promise) para evitar problemas de concurrencia y sobreventa.

Stack Tecnológico

Node.js (Módulos ES) Express PostgreSQL (Supabase) pg-promise (Transacciones) Meta Cloud API (WhatsApp) Webhook Security (x-webhook-secret)

Panel Administrativo

CRM de Control e Indicadores

  • Indicadores Dinámicos: Tarjetas superiores que calculan al instante el total de ventas, pendientes y confirmados.
  • Simulador de Pago: Botón que dispara el flujo de pasarela de pago simulado usando autenticación secreta.
  • Notificaciones en Vivo: Al aprobar un pedido en el CRM, el cliente recibe un WhatsApp automático de confirmación.

Visualización de Datos Moderna

Diseñado con Inter, sombras suaves, y modo Claro/Oscuro con persistencia local para confort visual del operador.

Conectores Rápidos de Chat

Apertura directa del historial de chat del cliente desde la misma tabla de pedidos.

Garantía de Demo

Resiliencia y Plan B (Simulador)

El Problema con APIs Externas

Los tokens de WhatsApp Developer expiran cada 24 horas y los webhooks públicos (Ngrok) cambian de URL, lo que puede arruinar demostraciones críticas.

La Solución: Plan B de Simulación

Un simulador de chat embebido que hereda toda la lógica conversacional de la base de datos y permite chatear directamente en la web. No requiere tokens, no consume Internet y garantiza la demo en cualquier escenario.

El Futuro

Conclusiones del MVP

Objetivos Cumplidos

Consumo exitoso de la API oficial de Meta, creación de CRM y API local de solicitudes funcionando integradas.

Robustez y Seguridad

Control de sesión en base de datos PostgreSQL resistente a fallos e integridad de inventario robusta.

Futuro Escalable

Arquitectura modular que permite integrar pasarelas de pago reales y catálogos ilimitados fácilmente.
